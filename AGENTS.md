## 1. Purpose

This SOP documents the standard workflow for developing, reviewing, approving, and maintaining Garden Project curriculum content—from raw sources to canonical teaching materials—so that curriculum development is:

- biblically outlined
- Christ-centered
- formation-oriented
- source-grounded
- reusable
- traceable
- reviewable
- maintainable across versions

**AI role (assistance, not authority)**
AI may assist with retrieval, classification, extraction, comparison, synthesis, editing, and formatting.

**AI boundary (no canon-making)**
AI may not make final canonical theological or curriculum decisions. Canonical approval belongs to the curriculum author or a designated human reviewer.

## 2. Core Content Layers

The Garden Project curriculum system distinguishes **layers** so that sources are preserved, evidence is traceable, and canonical content remains stable.

### A. Source Layer

**Definition:** Raw and historical material, including:

- uploaded files (Word/PDF/slide decks)
- old session drafts
- workshop notes
- framework notes
- program instructions
- translations
- archived versions
- research material

**Primary location:** A Source Library database (e.g., **Planted Source Library**) that tracks each source as its own record.

**Purpose:** Preserve evidence, history, language, illustrations, and prior development without prematurely rewriting or merging.

### B. Evidence Extraction Layer

**Definition:** Structured extraction appended to (or stored alongside) each relevant source.

**Purpose:** Identify what each source actually contributes *before* synthesis, so the canonical draft is grounded and reviewable.

**Required extraction categories (standard):**

1. Source identity (title, version/year, type, language)
2. Core claims
3. Key passages (only what the source actually uses)
4. Biblical-theological themes
5. Illustrations, metaphors, memorable teaching language
6. Discussion questions / prompts / activities
7. Formation applications (belief, perception, practice, embodiment)
8. Unique contribution
9. Repeated material (overlap across sources)
10. Human Review Needed (theological/exegetical/tone/accuracy risks)

### C. Coverage Audit Layer

**Definition:** A systematic review to confirm that all relevant sources have been found, linked, and extracted for a given session/resource.

**Purpose:** Distinguish between:

- **Retrieval gaps**
- **True content gaps**
- **Canonical decision gaps**

**Gap definitions**

- **Retrieval Gap:** Relevant content may exist, but the source has not yet been found, linked, or extracted.
- **Content Gap:** The source library genuinely does not contain enough material for a required section.
- **Canonical Decision Gap:** Relevant source material exists, but the author has not yet decided the official position, structure, wording, or emphasis.

### D. Canonical Content Layer

**Definition:** The current approved version of curriculum content; the **single source of truth** for teaching and downstream outputs.

**Examples:**

- Leader Notes
- Framework Notes
- Program Guides
- Workshop Guides
- canonical session summaries

**Purpose:** Provide stable, approved content for leaders and participants.

### E. Derivative Output Layer

**Definition:** Materials generated from canonical content, such as:

- participant guides
- leader packets
- slide decks
- handouts
- facilitator checklists
- shortened session versions
- youth adaptations
- translations

**Rule:** Derivative outputs should be generated from **canonical content**, not directly from raw sources.

## 3. Standard Development Workflow

**Standard sequence**

Inbox → Classify → Relate → Extract → Coverage Audit → Canonical Draft → Human Review → Revision → Approval → Canonical → Derivative Outputs → Archive

### Inbox

**What it is:** Newly uploaded or imported source material.
**Required action:** Preserve the original source and assign a temporary status (e.g., *Inbox*).

### Classify

**Goal:** Add conservative metadata without inventing uncertain information.
**Identify (as supported by evidence):**

- source type
- version/year
- language
- related curriculum
- related session
- related framework/program/workshop
- probable relevance

**Rule:** Do not invent uncertain metadata; record uncertainties explicitly.

### Relate

**Goal:** Link sources to the curriculum structure they support.
**Link to (as applicable):**

- the appropriate session (canonical sessions database)
- the appropriate Leader Note (canonical leader notes database)
- related framework/program/workshop pages

**Rule:** Allow multiple relations when one source supports more than one item.

### Extract

**Goal:** Create a structured evidence extraction (using the standard categories).
**Rules:**

- Do not merge content across sources at this stage.
- Do not silently correct theological, exegetical, historical, or factual claims.
- Preserve strong original language; flag risks rather than rewriting them away.

### Coverage Audit

**Goal:** Ensure all relevant sources have been found and processed *before* canonical drafting.
**Search for (required categories):**

- Word docs, PDFs
- slide decks / visual sources
- older versions
- translations
- workshop materials
- session notes
- framework sources

**Rules:**

- Require evidence for why each source is relevant.
- Flag retrieval gaps before concluding material is missing.

### Canonical Draft

**Goal:** Draft canonical content using only verified inputs.
**Draft using only:**

- verified sources
- completed evidence extractions
- approved session properties (title, Big Idea, key passages)
- approved templates and style guides

**Requirements:**

- consolidate repeated material
- preserve strong original language where appropriate
- distinguish essential vs optional content
- do not invent unsupported claims
- mark unresolved issues clearly (do not "paper over" them)

### Human Review

**Goal:** Human evaluation and decision-making before anything becomes canonical.

**Review criteria (minimum):**

- biblical faithfulness
- Christ-centeredness
- canonical storyline coherence
- theological precision
- pastoral tone
- formation goal clarity
- session distinctiveness
- relationship to surrounding sessions
- suitability for seekers/new believers
- clarity for leaders
- unnecessary duplication
- language requiring revision

### Revision

Revise only after review comments are recorded. Track changes so the review process remains auditable.

### Approval

The author or designated reviewer marks the content as approved.
**Rule:** No content should be treated as canonical before approval.

### Canonical

The approved page becomes the current single source of truth (canonical layer).

### Derivative Outputs

Generate leader packets, participant guides, slides, handouts, and adaptations **only from canonical pages**.

### Archive

Preserve old versions and source material for history and traceability.
**Rule:** Do not delete superseded material unless explicitly approved.

## 4. Required Quality Gates (Canonical Session Checklist)

Each canonical session must pass these gates before approval.

### Source Coverage

- [ ] All known relevant sources are linked
- [ ] Slide decks and visual sources were checked
- [ ] Older versions were considered
- [ ] Missing sources were flagged
- [ ] Retrieval gaps were resolved or documented

### Biblical Integrity

- [ ] Key passages are treated in context
- [ ] Supporting passages do not replace the primary text
- [ ] Claims are supported by Scripture or identified source material
- [ ] Difficult/debated interpretations are handled carefully
- [ ] Overstated claims are revised (not merely removed)

### Christ-Centeredness

- [ ] The session connects coherently to Christ
- [ ] Christ is not added artificially
- [ ] The gospel is not reduced to isolated moral advice
- [ ] The session fits the biblical story from creation to new creation

### Formation

- [ ] The session identifies what participants should see/believe/desire/practice/embody
- [ ] Application flows from the text and Big Idea
- [ ] Prayer/response is included
- [ ] The formation goal is realistic for one session

### Curriculum Coherence

- [ ] The session has a distinct role in the curriculum
- [ ] It connects to the previous session
- [ ] It prepares for the next session
- [ ] It avoids unnecessary repetition
- [ ] Frameworks/programs/workshops are correctly related

### Leader Usability

- [ ] Leaders can identify the essential movement
- [ ] Optional content is clearly marked
- [ ] Common misunderstandings are addressed
- [ ] Time expectations are realistic
- [ ] Discussion questions support the formation goal
- [ ] Leader cautions are included where necessary

### Tone and Audience

- [ ] Language is seeker- and new-believer-friendly
- [ ] Tone is gracious and truthful
- [ ] Technical terms are explained
- [ ] Claims are pastorally responsible
- [ ] Writing reflects the current Garden Project style

## 7. AI Responsibilities and Boundaries

| AI May | AI May Not |
|---|---|
| Search connected sources | Approve canonical theology |
| Classify documents | Silently resolve disputed interpretations |
| Identify likely relations | Invent missing source support |
| Extract evidence | Treat a retrieval failure as a content gap |
| Compare versions | Overwrite canonical pages without permission |
| Identify repetition | Delete historical sources |
| Flag contradictions and risks | Decide which theological position represents The Garden Project |
| Draft from verified evidence | Promote drafts to canonical status |
| Format content into templates | Generate final derivative assets from unapproved drafts |
| Generate derivative materials from canonical pages |  |

## 10. Pilot Case: Session 8 (Planted.)

**Session:** S8
**Title:** Eternity Planted
**Big Idea:** Eternal life begins now because God's future has entered the present in Christ.
**Key passages:** John 17:3; Ecclesiastes 3

**Pilot process (high-level)**

- Initial source extraction (structured, per-source; no merging)
- Identification of repeated themes (presence, heaven/earth, already/not yet, eternity planted)
- Identification of risky wording needing human review (overstatements; translation/nuance)
- Discovery of possible retrieval gaps (e.g., older versions, workshops, large attachments)
- Source-coverage audit to separate:
  - retrieval gaps vs content gaps vs canonical decision gaps
- Distinction between neighboring-session material and Session 8 central content
- Recommendation: delay final canonical drafting until coverage is complete and human review gates are satisfied

Source → Evidence → Coverage → Canonical Decision → Canonical Content → Derivative Output

**Governing statement**

Evidence supports the work.
Human judgment establishes the canon.
Canonical content guides every output."

## 12. Implementation Recommendations

1. **Can implement immediately (no database changes required)**
   - Use existing Source Library + canonical databases as-is.
   - Apply the extraction categories as a standard appendix on source pages.
   - Run coverage audits before drafting canonical revisions.
   - Add a Canonical Decision Log section to session workspaces/pages (as notes), without changing databases.
2. **Should remain manual**
   - Final theological decisions, emphasis, and approval
   - Pastoral tone decisions
   - Any disputed interpretation resolution
3. **Optional future enhancements (do not build yet)**
   - A dedicated "Canonical Decision Log" database (only if needed for scale)
   - Automated status transitions (only after the workflow stabilizes)
4. **Should not be built yet**
   - Duplicate Sessions/Leader Notes databases
   - Auto-promotion pipelines that treat drafts as canonical
5. **Recommended next action**
   Complete the Session 8 source-coverage audit, resolve retrieval gaps, then draft Session 8 Leader Notes v1 for human review.
